# 06 · 量化评估说明

## 1. 测试任务集

文件：`tests/tasks.json`（**22 条**，对齐实习方案 Day6 任务 24 的四类分布）

| 类别 | 条数 | 说明 | 示例 |
|---|---|---|---|
| 简单统计 | 8 | 单工具即可完成 | 「这个文件有哪些列？」「计算 (3+5)*12」 |
| 多维分析 | 6 | 需要筛选 / 分组 / SQL | 「用 SQL 查询价格大于 100 的记录」 |
| 跨表 / 跨月对比 | 4 | 需要聚合 + 图表 / 环比 | 「对比各地区销量，画一张柱状图」 |
| 边界用例 | 4 | 脏数据 / 无效输入 / 高风险 | 「统计 xyz 这一列的销量」「执行 DROP TABLE demo」 |

单条任务结构：

```json
{
  "id": 3,
  "category": "简单统计",
  "question": "各地区的销量总和是多少？",
  "expect_any": ["北京", "上海", "广州"],
  "expect_tools": ["stats_group_agg"]
}
```

- `expect_any`：回答中至少命中一个关键词才算成功
- `expect_tools`：期望调用的工具（用于计算工具调用准确率）

## 2. 六指标口径

| 指标 | 评估对象 | 计算方式 | 优化方向 |
|---|---|---|---|
| 任务完成率 | 端到端 | 成功任务数 / 总任务数（无异常 + 回复非空 + 命中 `expect_any` + 不含 `forbid_any`） | 优化 Prompt、工具描述 |
| 工具调用准确率 | 单步 | 期望工具中被实际调用到的比例（无期望工具的任务不计入） | 优化工具描述与 Schema |
| 平均执行步数 | 轨迹 | 完成任务的工具调用次数均值（越少越好） | 优化规划策略 |
| 单任务 Token 成本 | 资源 | prompt + completion Token 均值 | 上下文压缩、记忆优化 |
| 平均响应时长 | 体验 | 端到端耗时（**串行跑才准确**） | 异步调用、工具并发 |
| 轨迹合理性 | 轨迹 | `--judge` 时 LLM-as-Judge 打 1–5 分；未启用时用「步数落在 1–6 步」启发式 | 改进 ReAct Prompt |

## 3. 运行方式

```bash
python eval.py                  # 基线 + 两组消融（默认 8 线程并发）
python eval.py --judge          # 额外启用 LLM-as-Judge（更慢、更贵，但轨迹合理性更可信）
python eval.py --baseline-only  # 只跑基线（省钱）
python eval.py --workers 1      # 串行：响应时长指标准确
python eval.py --workers 16     # 提高并发（注意上游限流）
```

> 并发说明：LLM 请求是网络 I/O，线程池可显著缩短总耗时；
> 但并发下 `latency_ms` 含排队等待，只有 `--workers 1` 时的「平均响应时长」才是真实值。

## 4. 产出文件

| 文件 | 内容 |
|---|---|
| `tests/eval_results.csv` | 逐条结果：变体 / 任务 ID / 类别 / 是否成功 / 步数 / 调用工具 / 准确率 / Token / 延迟 / Judge / 错误 / 回答片段 |
| `tests/eval_metrics.csv` | 各变体六指标汇总 |
| `tests/eval_ablation.png` | 消融对比柱状图（完成率 / 准确率 / 步数 / Token） |

> `.gitignore` 默认忽略这三个产物；需要作为交付证据提交时，删除 `.gitignore` 中对应三行即可。

## 5. 内置消融变体

| 变体 | 说明 | 预期收益 |
|---|---|---|
| `baseline` | 无额外提示 | —— |
| `prompt_opt` | Thought 引导 + Few-shot 示例 | 任务完成率 +10~20% |
| `tool_desc` | 补充「何时用 / 何时不用」说明 | 工具调用准确率 +15~30% |

运行后会在终端打印「消融对比（相对基线）」，形如：

```
[tool_desc] 优化②：工具描述增强（何时用 / 何时不用）
   任务完成率: 0.8636 -> 0.9545  (+0.0909)
   工具调用准确率: 0.8125 -> 0.9500  (+0.1375)
   ...
```

## 6. 如何扩展评估

1. **加任务**：往 `tests/tasks.json` 的 `tasks` 数组里加条目（字段同上）
2. **换数据**：修改 `eval.py::run_one_task` 里的 `csv_path="demo.csv"`
3. **加变体**：在 `eval.py::VARIANTS` 中增加键值对（键名 + 描述 + 追加到 System Prompt 的文本）
4. **改判定**：调整 `is_success`（完成判定）与 `REASONABLE_STEPS_RANGE`（轨迹合理性区间）

## 7. 评估小贴士

- 先跑 `--baseline-only` 确认链路通，再跑全量，避免浪费 Token
- 模型温度已设为 `0`（`llm.py::TEMPERATURE`），结果可复现
- 失败任务重点看 `error` 与 `reply` 两列：是工具报错、超时，还是判定关键词太严
- 答辩时建议展示：`eval_metrics.csv`（六指标）+ `eval_ablation.png`（优化前后对比）
