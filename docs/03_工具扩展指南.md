# 03 · 工具扩展指南（新增一个工具 ≤ 30 分钟）

## 1. 设计目标

> **新增工具不需要改动 `agent.py` / `api.py` / `app.py` 任何一行代码。**

`tools/registry.py` 在启动时扫描 `tools/` 目录，自动完成：

1. 发现所有 `@tool` 装饰的函数（文件名以 `_` 开头的模块跳过，如 `_template.py`）
2. 从函数签名 + 类型注解生成 JSON Schema
3. 把工具名 + docstring 写进 System Prompt 的【可用工具清单】
4. 出现在 `GET /tools` 响应与前端「工具箱」面板

```
tools/my_tool.py（新增文件）
        │  自动发现
        ▼
tools/registry.py ──▶ agent.py 的 System Prompt ──▶ 大模型可见
        │
        ├──▶ GET /tools ──▶ 前端工具箱
        └──▶ docs 文档（可脚本导出）
```

## 2. 四步接入（计时 ≈ 25 分钟）

### Step 1 · 复制模板（1 分钟）

```bash
cp tools/_template.py tools/my_tool.py
```

> 文件名**不要**以 `_` 开头，否则会被注册中心跳过。

### Step 2 · 改写函数（15 分钟）

```python
from langchain_core.tools import tool
from .guard import safe_path

RISK_LEVEL = "low"          # 可选：low / medium / high

@tool
def top_n(csv_path: str, column: str, n: int = 3) -> str:
    """取某一列数值最大的前 N 条记录。
    适合"找出销量最高的 3 个品类"这类问题；需要按某列分组求和时请用 stats_group_agg。"""
    try:
        safe_path(csv_path)                        # ① 路径护栏
    except ValueError as e:
        return f"错误：{e}"
    try:
        import pandas as pd
        df = pd.read_csv(csv_path)
        if column not in df.columns:               # ② 列名校验要返回可用列
            return f"错误：列不存在，可用列 {list(df.columns)}"
        return df.nlargest(n, column).to_string(index=False)
    except Exception as e:
        return f"错误：{type(e).__name__}: {e}"    # ③ 出错返回人话
```

### Step 3 · 重启并验证（2 分钟）

```bash
uvicorn api:app --reload --port 8000
python -m tools.registry          # 新工具应出现在打印列表里
curl http://localhost:8000/tools  # GET /tools 应包含新工具
```

### Step 4 · 补自测（5 分钟）

在 `tests/test_tools.py` 中追加：

```python
from tools.my_tool import top_n
run_case("TopN 取前 3", lambda: top_n.invoke({"csv_path": CSV, "column": "quantity", "n": 3}), "北京")
```

## 3. 三条铁律（踩过的坑）

| 铁律 | 原因 | 反例 |
|---|---|---|
| **必须写参数类型注解**（`csv_path: str`） | 模型靠注解生成参数；缺失会导致参数填错 | `def f(csv_path):` |
| **必须写 docstring，并写清「何时不用」** | docstring 就是模型看到的工具说明书 | 只写「统计数据」 |
| **必须返回字符串** | 工具结果要塞回对话消息；DataFrame / 图片对象会让接口报 400 | `return df` |

补充建议：
- 出错时**返回错误文本**而不是抛异常，让模型能读取提示自我纠正（如返回「可用列」）
- 涉及文件路径一律先调用 `guard.safe_path`
- 输出长度控制在 ~2000 字符内，避免挤占上下文（必要时截断并说明）

## 4. 注册中心 API

```python
from tools.registry import get_tools, catalog, prompt_catalog, tool_names

get_tools()        # -> list[BaseTool]，已按 TOOL_ORDER 排序
catalog()          # -> [{"name","description","parameters","risk"}]
prompt_catalog()   # -> 注入 System Prompt 的多行文本
tool_names()       # -> ["profile_csv", ...]
```

**控制展示顺序**：把工具名加入 `tools/registry.py::TOOL_ORDER`，未列出的工具按名称排在末尾。

**标记高风险**：模块内声明 `RISK_LEVEL = "high"`，`GET /tools` 会返回 `risk=high`，便于 HITL 重点关注。

## 5. 常见扩展场景

| 场景 | 实现方式 | 参考 |
|---|---|---|
| 新增一个统计指标（如中位数、TopN） | 新增 `@tool` 函数 | `tools/stats_tool.py` |
| 接入外部 API（天气 / 搜索） | 在工具内 `requests.get`，密钥从 `.env` 读取 | 需新增 `requests` 调用与超时 |
| 输出非文本内容（图片 / 文件） | 保存文件后返回**相对路径字符串** | `tools/chart_tool.py` |
| 需要多步组合的复杂能力 | 拆成多个小工具让模型编排，而不是一个巨型工具 | 设计原则见下 |

## 6. 设计原则：粒度怎么切

- **让模型「选工具」优于让模型「填参数」**：把「一个函数 + operation 参数」拆成多个具名工具，
  工具调用准确率明显提升（本项目的 `stats_*` 五兄弟就是这么来的）
- **一个工具只做一件事**：职责单一 → docstring 好写 → 模型好选
- **命名自解释**：`stats_group_agg` 比 `stats_tool` 更容易被正确调用
